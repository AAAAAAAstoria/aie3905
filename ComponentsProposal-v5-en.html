World Vision

worldvision.org ↗

World Vision 是一个全球性的基督教人道主义组织，与儿童、家庭和社区合作，处理贫困与不公带来的长期问题，也参与灾害准备、紧急响应以及灾后恢复。其网络覆盖近 100 个国家，因此课程项目有机会接触真实的人道主义场景与一线需求。

本课程合作由 World Vision 相关亚太或东亚区域团队推动。正式演示和书面材料中使用的区域团队名称，应以合作方最终确认为准。

面向真实使用者一线工作人员、社区负责人和人道主义决策人员，而不是抽象的“用户”。
关注完整灾害周期灾前准备、预先行动、紧急响应、恢复与长期社区韧性。
我们的合作原则帮助现有组织更有效地工作，保留社区参与和人工决定权。

01

数据 · 预测 · 空间建模 · 可视化

World Model：灾害预测与场景模拟

目标是建立一个可探索的数字世界，使研究者和实践人员可以输入条件，观察灾害可能的发展及其对特定地区的影响。

学生需要完成的工作

  1. 确定一个清晰的东南亚研究区域，并选择一组有联系的灾害与预测任务。可从台风轨迹和强度、强降雨与洪水危害开始，再按数据条件扩展地震或其他灾害。
  2. 收集多个历史事件及其连续时间快照，连接气象、水文或地质、地形、人口、道路、建筑、关键设施和灾后观测，并记录数据许可、来源、时间与版本。
  3. 完成清洗、质量检查和空间时间对齐，明确缺失值、覆盖不足与不确定性。
  4. 为每类预测任务建立可解释的规则或持续性基线，并比较传统统计/机器学习模型、开源深度模型和合适的 SOTA 开源模型；根据数据规模选择直接推理、微调或重新训练。
  5. 设计统一的输入输出接口，形成一系列相关预测：例如台风轨迹、登陆时间、强度和风圈，洪水水位、流量、危害指数、淹没范围与深度，以及人口和设施暴露。
  6. 制作交互式地图或时间轴，支持历史事件回放和假设情景模拟。

这里的“World Model”是什么意思？

它不是要求训练一个通用基础模型，而是建立一个数据驱动的地区与灾害数字表示。系统需要把环境状态、灾害演化和暴露对象连接起来，并允许用户改变输入后重新模拟结果。

最低可用问题
给定某个时间、位置和环境状态，系统能否在多个历史事件上稳定预测接下来可能发生什么，展示哪些地方、人群和设施可能受到影响，并说明模型的不确定性？

02

后台监测 · Agent · RAG · 人工审核

台风 Agent Harness：从权威通报到行动建议

课程以台风作为主要案例：让系统全天候监测可信来源，识别有意义的变化，并把实时情景与经过治理的灾害知识连接起来。每个小组应围绕一个明确灾种完成端到端系统。

学生需要完成的工作

  1. 选择一个灾害主题和目标地区，并围绕它完成整个 Harness。推荐以台风为主案例；也可以改为洪水、地震或其他具有可靠权威信息源和 SOP 的灾害。
  2. 确定权威信息源和辅助信息源，开发定时抓取或 API 连接，并记录每次通报的时间、版本和原文。
  3. 把连续通报转换成结构化事件状态，识别路径、强度、范围、时间或预警级别的实质变化。
  4. 建立经过筛选和版本管理的 RAG 知识库，涵盖 SOP、响应标准、案例、风险手册和本地约束。
  5. 根据当前事件检索证据，生成分优先级的风险提示或行动建议，并附上引用、不确定性和缺失信息。
  6. 设置权限、人工确认、失败降级和审计日志。系统不能自行发布官方预警或执行高风险行动。

Harness 不只是一个聊天机器人

Harness 是智能体的运行和治理框架：它决定何时启动、调用哪些工具、保留什么状态、使用哪些知识，以及哪些输出必须由人审核。

多灾种预测 · LLM Harness · GIS Agent · 学术产出

Disaster Intelligence Benchmark：证明系统是否有效

这个组件从项目第一天就独立开展，包含三类互补测试：多灾种真实事件预测、轻量 LLM Harness 固定流程，以及面向 Codex、Claude Code 等系统的开放式 GIS 长程任务。

学生需要完成的工作

  1. 访谈 World Vision 或其他行业人员，明确三条评测赛道中的真实使用者、关键决策、可接受风险，以及哪些错误最严重。
  2. 建立符合 World Model 测试需要的多灾种真实事件集。至少覆盖若干台风、洪水、地震或其他事件，保存连续时间快照、预测输入、隐藏真值和空间影响结果。
  3. 提供一组基础预测组件或标准化预测输出，例如台风轨迹、洪水危害指数和暴露估算；同时准备少量清晰 SOP、案例材料、RAG 语料和可审计的 Web Search 接口。
  4. 构建轻量 Harness 环境，测试现有 LLM 能否按固定步骤读取通报、调用预测组件、搜索资料、检索 SOP、核对证据并生成结构化建议。
  5. 设计开放式 GIS 长程任务，让 Codex、Claude Code 等 Harness 系统自行规划、查找和核验资料、处理空间数据、运行分析并产出地图、数据和可复现报告。
  6. 为三条赛道分别设计指标、基线、隐藏测试、专家盲评和失败分析，防止答案泄漏，并说明结果如何反馈给 World Model 或 Harness。

Benchmark 要同时测“模型”和“做事的系统”

第一条赛道测预测模型；第二条赛道把 LLM 放进受控 Harness，测它能否正确调用工具和遵循 SOP；第三条赛道测长程智能体面对复杂、开放、需要 GIS 操作的真实任务时能否独立完成工作。

核心问题
在隐藏结果和一致工具条件下，我们能否公平比较预测模型、单个 LLM 与完整 Harness，并指出它们在哪些灾种、步骤和任务复杂度上可靠或失败？
TRACK 01

多灾种 World Model Benchmark

用多个真实灾害事件检验预测与空间影响模型，支持跨事件、跨灾种和不同提前量的公平比较。

  • 台风：轨迹、强度、登陆时间、风圈
  • 洪水：水位、流量、危害指数、淹没范围
  • 地震或其他灾害：震度、影响范围、暴露
  • 隐藏真值、时间外测试与不确定性校准
TRACK 02

轻量 LLM Harness Benchmark

向不同 LLM 提供相同的基础预测组件、简单 SOP、RAG 知识库和 Web Search，观察它们能否完成固定流程。

  • 工具选择、参数填写与步骤完成率
  • Web 资料核验、引用正确性与时效性
  • SOP 遵循、建议质量与安全升级
  • 相同 Harness 下比较不同 LLM
TRACK 03

开放式 GIS 长程任务

给完整 Harness 一个复杂任务说明，让它自行拆解工作、查找资料、编写代码、运行 GIS 分析并交付可核验成果。

  • 面向 Codex、Claude Code 等智能体系统
  • 多源数据搜索、下载、清洗与坐标对齐
  • 空间分析、地图、表格和研究报告
  • 过程日志、可复现性、恢复能力与人工介入

专家参与行业人员共同定义高风险错误、权重和可接受阈值。
最低交付
  • 三条赛道的 Benchmark Specification
  • 多灾种 Event Case 与隐藏真值
  • 轻量 Harness、GIS 长程任务和统一评估工具
课堂演示
  • 多模型预测的隐藏测试对比
  • 不同 LLM 完成固定 Harness 步骤的对比
  • 一个复杂 GIS 长程任务的完整回放
主要验收
  • 任务是否反映真实需求
  • 指标是否可靠且可复现
  • 是否能区分模型优劣并指导改进

建议的第一学期 MVP

  • Track 01：从 20–30 个高质量多灾种 Event Case 起步，并保留多个时间快照和隐藏真值
  • Track 02：先提供 2–3 个基础预测组件、一个小型 SOP/RAG 语料库和 10–20 个固定流程任务
  • Track 03：设计 5–10 个需要多源数据与 GIS 操作的开放式长程任务，并定义可自动检查的交付物
  • 三个 Track 分别设置开发集与隐藏测试集，再用统一报告呈现性能、成本、失败模式和人工介入

潜在研究与论文方向

  • 灾害预测或暴露分析 Benchmark 数据集论文
  • RAG 是否提高灾害建议的事实性、可执行性和安全性
  • World Model 输出能否改善 Harness 的地点与人群优先级
  • 不同 LLM 在相同轻量 Harness 下的工具使用、Web 核验和 SOP 遵循能力
  • Codex、Claude Code 等长程智能体完成复杂 GIS 任务的能力边界
  • 自动指标与人道主义专家判断之间的一致性

项目特点：这不是一个轻量的“跑分项目”。它同时需要多灾种 Event Case、基础预测组件、轻量 Harness 环境和开放式 GIS 长程任务，对案例设计、工具封装、标注质量、实验控制、自动评估和行业沟通都有较高要求。做好后既能独立形成有影响力的 Benchmark 论文，也能为前两个组件提供统一、外部且可复现的评价框架。

共同工作方式

独立收集，可选协作，接口尽量兼容

五个小组默认独立收集数据和 Event Case，不要求建立全班共享数据集。小组之间可以并行开发，也可以自愿协作，交流公开数据来源、字段格式、标注说明、工具或模型输出；若希望做跨组件集成，再协商兼容接口和测试方式。

World Model 输出

灾害预测、风险或影响范围、暴露摘要、模型版本、不确定性与数据来源。

Harness 输出

通报变化、事件状态、检索证据、行动建议、缺失信息、人工决定与运行日志。

Benchmark 输出

多灾种测试案例与隐藏真值、基础预测工具、轻量 Harness、开放式 GIS 任务、指标、评分和失败分析。

阶段 1各组确定范围

每组选择灾害、地区、用户问题，并开始收集自己的案例与数据。

阶段 2建立最小闭环

各组定义自己的输入输出；有合作意向的小组再约定兼容字段。

阶段 3并行开发与验证

各组独立迭代；可自愿交换公开资源、模型输出或受控测试任务。

阶段 4独立演示，可选联动

每组展示自己的端到端成果；跨组件回放可作为扩展成果。

所有组件共同遵守的边界

  • 只支持专业判断，不替代官方预警机构。
  • 不自动下达疏散命令，不决定援助资格。
  • 不自主分配资源或直接向社区发布高风险信息。
  • 所有结果保留来源、版本、假设和不确定性。
  • 涉及个人或社区数据时遵守隐私和访问权限。
  • 关键输出必须可供人工确认、修改、拒绝和审计。
